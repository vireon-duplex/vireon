# task-queue

Production-grade **reactor-local execution engine** for Vireon — the
callback-based task scheduler that drains and runs work generated by
the IO Layer, Timer Wheel, and application code. IO-backend agnostic
(io_uring today; XDP / DPDK / IOCP future).

See [`DESIGN.md`](DESIGN.md) for the full architecture specification.

## Architecture

```text
+-------------------------------------------------------------------+
|                     TASK QUEUE (Reactor Core N)                   |
|                                                                   |
|  ── Producers ──────────────────────────────────────────────────  |
|  spawn()                  spawn_cross_thread()  schedule_after()  |
|    │                        │                     │                |
|    ▼                        ▼                     ▼                |
|  TaskPool ──► ReadyQueue    MpscInbox            DeferredRegistry |
|  (slab + gen,  (4-band FIFO,(lock-free            (Timer Wheel     |
|   cancel flag)  strict prio, ArrayQueue)          integration)     |
|                 aging)                                            |
|                                                                   |
|  ── Reactor tick ──────────────────────────────────────────────  |
|  tick(ctx, now_ns)                                                |
|    │                                                              |
|    ▼                                                              |
|  drain_inbox ──► expire ──► Scheduler.select ──► Executor.run     |
|  (MPSC → ready)  (deadline)  (FIFO + aging)    (budget-bounded)   |
|                                                                  │
|    └─► TaskResult {Done | Error | Reschedule} ──► recycle / push  |
+-------------------------------------------------------------------+
```

## Quick start

```no_run
use task_queue::{Task, TaskContext, TaskPriority, TaskResult, TaskQueueBuilder};

struct Echo { n: u32 }
impl Task for Echo {
    fn run(&mut self, _ctx: &mut TaskContext) -> TaskResult {
        # let _ = self.n;
        TaskResult::Done
    }
}

let mut tq = TaskQueueBuilder::new().capacity(1024).build()?;
let handle = tq.spawn(Echo { n: 42 }, TaskPriority::Normal)?;
tq.cancel(&handle);

let mut ctx = TaskContext::new(0, 0);
let r = tq.tick(&mut ctx, 0);
assert_eq!(r.cancelled, 1);
# Ok::<(), Box<dyn std::error::Error>>(())
```

## Relationship to other crates

| Crate | Role |
|-------|------|
| `io-layer/io`         | Calls `spawn()` on IO completion to schedule stream-event work. |
| `runtime-layer/timer-wheel` | Fires deferred tasks via `on_timer_fire(slot_idx)`. `schedule_after` registers a deferred task; the reactor drives firing. |
| `runtime-layer/send-queue` | Schedules retransmit / flush tasks after CQE processing. |

The Task Queue **never** touches `io_uring`, `RawFd`, or any IO
backend — it is pure user-space scheduling.

## Design choices

- **Callback-based, not Future-based.** `Task::run(&mut self, &mut
  TaskContext) -> TaskResult` completes synchronously. No `poll`,
  no waker, no async runtime. Sub-µs per-task overhead.
- **Slab pool with generation counters.** Each task lives in a slot
  addressed by `(slot_index, generation)`. The generation is bumped on
  free so stale handles are rejected. `TaskId` packs both into a
  single `u64`.
- **4-band strict-priority FIFO.** High → Normal → Low → Background,
  FIFO within each band. `pop_next()` walks bands in order.
- **Aging tracker.** Tasks waiting longer than `aging_threshold_ns`
  are promoted one band per tick to prevent starvation.
- **Bounded execution budget.** Each tick is capped by
  `batch_max_tasks` (count) and `batch_max_time_ns` (wall clock). An
  IO-heavy reactor can never be starved by task floods.
- **Lazy cancellation.** Each task carries an `Arc<AtomicBool>` cancel
  flag; `cancel()` flips it, the executor checks it before `run()`.
  No lock contention, no ABA.
- **MPSC inbox for cross-thread submission.** `spawn_cross_thread`
  pushes into a lock-free `crossbeam_queue::ArrayQueue`; the owning
  reactor thread drains it on each `tick()`. The queue itself is
  `!Sync` (it owns `Box<dyn Task>` slots), so cross-thread producers
  need a separate `InboxHandle` (Phase 2) — Phase 1 is single-reactor.
- **Zero allocation on hot path.** Pool slots are pre-allocated; the
  per-tick batch is a reusable scratch buffer; reschedules reuse the
  same slot.
- **Shutdown phase machine.** `Running → Draining → Stopped` with a
  best-effort grace-period drain. New spawns rejected after
  `shutdown()` begins.

## Benchmarks

The crate ships a 6-binary Criterion suite covering spawn latency,
batch tick throughput, scheduler isolation, saturation behavior,
inbox scaling, and sustained soak.

```sh
cargo bench -p task-queue                              # full Criterion suite
cargo bench -p task-queue --bench spawn                # single bench
cargo bench -p task-queue --bench spawn -- \
    --sample-size 20 --measurement-time 0.5            # quick smoke

# Sustained-load soak — detect pool/recycler leaks.
cargo bench -p task-queue --bench soak -- \
    --measurement-time 60 --sample-size 5
```

### Bench inventory

| Binary | Concern |
|--------|---------|
| `spawn`       | `spawn()` latency + burst throughput (16 / 64 / 256) + counter-task overhead |
| `tick`        | Full drain at depths 16–1024, empty fast-path, mixed-priority drain |
| `scheduler`   | `FifoPolicy::select` isolated, full tick mixed-priority, raw `ReadyQueue` push/pop |
| `saturation`  | Spawn-to-fill at 50–99% fill levels, full-drain tick at fill, sustained 95% cycle |
| `mpsc`        | `spawn_cross_thread` latency, burst push throughput (16–1024), consumer drain, sustained inbox pressure |
| `soak`        | 16×256 spawn→tick cycle + 32×512 steady-state; sanity-asserts pool is fully recycled each tick |

### Smoke-test numbers (single run, your Mileage Will Vary)

| Bench | Result |
|-------|--------|
| `spawn/single`              | ~180 ns / call |
| `spawn_burst/n=256`         | ~6.7 µs (~38 Melem/s) |
| `spawn_counter/single`      | ~180 ns / call |

### Leak detection

The `soak` bench recycles the queue across iterations and
`debug_assert!`s that `free_slots()` returns to capacity after every
drain. If pool slots or batch buffers leak, the assertion fires.

```sh
/usr/bin/time -v cargo bench -p task-queue --bench soak -- \
    --measurement-time 300 --sample-size 3
```
